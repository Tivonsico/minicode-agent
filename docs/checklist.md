# minicode 验收清单

状态：2026-09-10 完成本地实现及自动化检查。已勾选项的测试证据见 [验证记录](verification.md)；未勾选项保留待验证，不代表未编写代码。

当前配置方式（2026-10-08）：`.env` 只要求密钥、API 地址和模型名；窗口由 `backend/models/` 自动解析，不再读取 `CONTEXT_WINDOW`。输出预算可选，元数据接口与 Models.dev 目录均无法确认时明确报错。下列旧清单保留历史验证记录，旧手动预算要求已被本次重构取代。

## 已确认配置与接口

- [x] CFG-01：实现语言为 Python，Shell 使用 PowerShell；从 Windows PowerShell 可启动终端应用。
- [x] CFG-02：使用智谱官方 base_url `https://open.bigmodel.cn/api/paas/v4/`，对话请求落到 `chat/completions`；用户指定模型为 `GLM-5.3-Flash`。2026-09-10 真实请求返回 HTTP 200，响应模型名为 `glm-5.3-flash`；程序仍原样发送配置值，不静默替换模型。
- [x] CFG-03：提供 `.env.example`，真实 `.env` 被 Git 忽略且不含于日志；示例仅含占位密钥。缺失密钥时在发请求前提示配置，不输出密钥。
- [x] CFG-04：配置明确的上下文窗口 C 和输出预留 O，校验 `0 < O < C`；未知窗口要求配置或验证，不把示例 `max_tokens=65536` 当作窗口大小。
- [ ] CFG-05：记录所选模型的工具调用、流式 usage、思考模式及输出限制验证结论；未经证实不强制发送用户示例中的 thinking、temperature 或输出上限。
- [x] API-01：请求保留 `system`、`user`、`assistant`、`tool`；工具结果使用对应 `tool_call_id`，系统提示词每个有效请求包含一份，不追加成 user 历史。
- [x] API-02：普通正文允许纯文本，内部层统一结构；不通过提示词要求正文输出自定义 JSON 才能使用工具。
- [x] API-03：同一响应含正文和工具调用时执行工具、回传结果再请求模型，不因正文非空而结束。
- [x] API-04：流式多个工具调用分别合并参数；只在完整响应及参数校验通过后执行。工具不存在、JSON 不合法或 Schema 不匹配时不产生文件或进程副作用。
- [x] API-05：结束原因由智谱适配层映射；正常停止且无工具调用可结束本轮，`length`、错误、拒答等原因单独记录，不把流连接关闭一律当成功。

## 状态与主循环

- [x] STATE-01：session、turn、message、request、tool_call 各有可关联标识；事件包含递增序号与时间，不把每个流式片段算成独立完整消息。
- [x] STATE-02：`is_final` 仅表示本轮最终回复；“请提供文件路径”可为最终回复，但不因此记录用户任务已完成。
- [ ] STATE-03：采用建议状态：会话 `idle/active/closed`；轮次 `running/completed/failed/interrupted/paused`；消息 `streaming/complete/partial/error/cancelled`。轮次 `completed` 只表示正常回复结束。
- [ ] STATE-04：工具状态区分 `pending/awaiting_approval/running/succeeded/failed/rejected/cancelled/unknown`；调用结束不等于成功，结果无法确认不伪造成功或失败。
- [x] STATE-05：轮次中断、失败或暂停时记录独立原因；正文已输出但断流保留为 partial 且 `is_final=false`；输出截断暂停，不自动当正常最终回复。
- [x] STATE-06：终态事件不可被迟到的流式结果改回 running；只由明确的用户继续动作恢复暂停/中断流程。
- [x] LOOP-01：输入任务后，可观察“模型工具请求 → 工具结果 → 再次模型请求 → 最终回复”的事件链。
- [x] LOOP-02：每轮最多 30 次主模型请求；发出第 31 次前暂停并保存。建议计实际网络尝试，自动重试也计入 30 次，SDK 不另做隐藏重试。
- [ ] LOOP-03：用户继续后可获得新一段 30 次预算，已有消息、调用与原暂停点仍可追溯，不重放前一段已完成工具。
- [x] LOOP-04：压缩和长期记忆请求不占主模型 30 次额度，但有各自超时和失败处理，不在后台无限重试。

## 文件工具、并发与审批

- [x] TOOL-01：注册 ReadFile、WriteFile、EditFile、DeleteFile、Shell、Glob、Grep 共 7 个工具，提供 `name/description/inputSchema/execute/isReadOnly/isDestructive/isConcurrencySafe/category/validateInput` 对应能力；实际授权由执行器执行。
- [x] TOOL-02：ReadFile、Glob、Grep 的独立调用允许有界并发；WriteFile、EditFile、DeleteFile、Shell 串行，且执行期间其他工具不运行。
- [x] TOOL-03：输入调用序列“读 A、读 B、改 A、读 A”，前两项可并发，均结束后才改 A，最后一次读取看到新内容；返回结果始终对应原工具调用 ID。
- [x] PATH-01：文件工具拒绝 `../`、绝对项目外路径及通过符号链接/目录联接指向项目外的读、写、删除、搜索；搜索不跟随越界目录。
- [ ] PATH-02：项目根以解析后的实际路径比较，不能通过大小写、相似路径前缀或替换链接绕过边界；执行前重新检查目标。
- [x] PATH-03：文件读取和搜索跳过 `.env`、实际环境密钥文件及私钥；`.env.example` 允许读取且仅含占位符；被拒绝内容不出现在模型输入或会话输出中。
- [x] PATH-04：普通文件工具不允许读取或修改 `.minicode/` 内部会话及长期记忆；只放行当前会话显式登记的工具输出供 ReadFile 分段读取。
- [x] PATH-05：程序加载 `.env` 的配置通道与模型文件工具分开；Shell 不宣称具备上述强制文件隔离，审批展示命令及目录。
- [x] EDIT-01：创建不存在的新文件自动执行；覆盖或编辑已有文件必须持有本轮有效读取内容及其版本指纹，否则要求先读取。
- [x] EDIT-02：读取后由外部程序修改文件，再执行写入或编辑时拒绝修改并要求重新读取，外部内容保留。
- [x] EDIT-03：精确编辑在旧文本不存在或匹配多处时拒绝，不猜测目标位置；修改成功后旧读取凭据失效，进一步修改先重新读取。
- [ ] EDIT-04：建议写入通过同目录临时文件和替换完成，避免半写文件；文档明确普通文件工具无法对不合作的外部进程提供绝对无竞态保证。
- [x] DEL-01：DeleteFile 仅删除单个普通文件；目录、项目根、内部数据和敏感目标按策略拒绝，不提供递归删除能力。
- [x] DEL-02：删除前展示目标路径并确认，授权绑定目标版本；审批后文件发生变化时原授权失效，不删除变化后的文件。
- [x] DEL-03：拒绝删除后文件仍存在；批准删除仅影响该目标。目录递归删除如通过 Shell 请求，仍受独立命令审批，不由 DeleteFile 执行。
- [x] APPROVE-01：项目内允许的只读、创建和编辑无需确认；每次删除与每次 Shell 执行都需确认，批准仅限该次调用及原参数。
- [x] APPROVE-02：审批展示操作、工作目录/目标和 Shell 超时；尚未批准或已经取消时无执行副作用。
- [x] APPROVE-03：拒绝作为 `rejected` 结果返回模型，不计工具失败次数；同一轮自动重复提交同一被拒绝操作时不再次弹审批或执行，用户明确改变授权后才可重新申请。

## Shell、失败与中断

- [x] SHELL-01：PowerShell 命令在项目根目录启动；完整命令和工作目录在审批界面可见，执行不额外打开可见终端窗口。
- [x] SHELL-02：默认超时 120 秒；申请更长时间时确认界面显示实际值，授权不能沿用较短超时的旧请求。
- [x] SHELL-03：记录 stdout、stderr、退出码及终止原因；非零退出作为工具失败回传，不能只因进程结束而视为成功。
- [x] SHELL-04：超时尝试终止进程及子进程，保存现有输出且不自动重跑；终止未确认时记录未知并暂停后续工具，避免与仍运行的进程重叠。
- [x] FAIL-01：网络错误或限流发生且未收到输出时，最多自动重试 2 次；已接收正文、推理或工具参数片段后断流则保存并暂停，不整段自动重发。认证或配置错误直接提示修复。
- [x] FAIL-02：工具名、规范化参数和错误类型相同的连续实际失败累计到 3 次时暂停；不同失败重新计数，成功清零；拒绝不累计。错误文本中的随机路径/时间不能造成相同错误无限逃逸计数。
- [x] CANCEL-01：Esc 取消当前模型接收、未执行工具和待审批请求，尝试终止正在运行的 Shell 及子进程；记录用户主动中断。
- [x] CANCEL-02：已完成的写入或删除不自动撤销；中断不能确认是否完成的操作标记 unknown。
- [x] CANCEL-03：中断后迟到的模型/工具结果可作为已启动操作的记录落盘，但不能触发下一工具或下一模型请求。
- [x] CANCEL-04：中断导致的部分参数不执行；只有系统确认前一执行已停止或明确暂停时才允许下一轮工具启动。

## 会话目录、输出与恢复

运行数据建议使用下列具体文件名，用户已确认每个会话独立目录及主文件引用同目录输出的方式：

```text
<project>/.minicode/
  sessions/
    <session_id>/
      session.jsonl
      session.meta
      outputs/
        <tool_call_id>.stdout.txt
        <tool_call_id>.stderr.txt
  long_memory/
    memory.json
  project.lock
```

- [x] STORE-01：运行数据在项目 `.minicode/`，整体被 Git 忽略；与源码 `memory/` 分离。
- [x] STORE-02：主 JSONL 追加用户消息、助手片段、完整消息、工具请求、批准/拒绝、工具结果及终止事件；生成中持续写入并刷新，正常结束、Esc 和退出时完成刷新。
- [x] STORE-03：流式片段与完整消息共享消息 ID；恢复和计数不会把两者重复显示、重复算消息或重复算 token。
- [x] STORE-04：JSON 格式 `.meta` 保存会话 ID、标题、摘要、消息数、各类及总 token、创建/活跃时间、最后终止方式；更新原子替换，缺失或损坏可从主日志重建。
- [x] STORE-05：末尾不完整 JSONL 记录保留供诊断，并从此前完整事件恢复；日志中间损坏则明确提示，不默默跳过。
- [ ] STORE-06：日志无法写入时停止新工具调度并显示存储故障，不能继续执行有副作用的操作却声称已保存；持久化保证限于已成功写入记录，不承诺未刷新缓冲在断电后保留。
- [x] OUT-01：超长工具输出完整存入所属会话 `outputs/`；主 JSONL 保存相对地址、工具关联及长度等定位信息，而非把正文重复嵌入主文件。
- [x] OUT-02：模型首次收到有限预览及内部输出定位信息，可用 ReadFile 按段读取本会话该输出；引用解析以所属会话目录为基准。
- [x] OUT-03：输出引用禁止 `../`、绝对路径及链接逃逸，不允许访问其他会话；被引用文件缺失时明确报告不可用，不当作空结果。
- [x] RESUME-01：启动默认新会话；输入 `/session` 后回车显示已有会话列表，选择仅加载并展示历史、最后状态和中断位置。
- [x] RESUME-02：用户明确输入“继续”后才恢复执行；选择列表项本身不请求模型也不运行工具。
- [x] RESUME-03：已经成功的写入、删除或 Shell 调用不因事件回放再次执行；结果未知的调用先展示并验证现状，不自动重跑。
- [x] RESUME-04：恢复后的 API 消息没有孤立工具结果或未配对的调用；程序明确记录中断/未知结果，不通过伪造成功修补协议。
- [x] LOCK-01：同一实际项目路径第二个实例提示正在使用，且不写内部数据；不同项目可分别启动。
- [x] LOCK-02：锁随进程退出/崩溃释放，残留锁文件本身不永久阻止重启；路径别名不能绕过同项目限制。

## 上下文、长期记忆与用量

- [x] CTX-01：可用输入预算为 `B=C-O`；有效输入预计占用达到 `0.8*B` 时触发压缩；统计包含提示词、工具描述、记忆、消息和必要协议开销。
- [x] CTX-02：大文件先分段；旧工具输出压缩为必要摘要、路径和行号/输出定位信息；保留当前任务、系统提示词和必要近期消息。
- [x] CTX-03：压缩仅替换有效上下文，不覆盖原 JSONL；压缩后调用和结果配对，正在进行的工具组不被拆散。
- [x] CTX-04：压缩失败保留原上下文；原输入仍小于等于 B 则继续，超过 B 则保存并暂停；压缩请求自身也不得超出模型预算。
- [x] CTX-05：生成压缩候选后重新检查协议与预算，摘要仍超限则明确暂停；API 意外返回窗口超限时保存并提示，不无限循环压缩或静默丢历史。
- [x] MEM-01：每轮正常最终回复后增量提取，Esc、失败、截断或上限暂停不触发该轮提取；只存用户明确表达的偏好、约束和事实，不存模型推测画像。
- [x] MEM-02：按项目隔离，条目保留来源会话、消息及用户陈述时间；新旧明确陈述冲突时以最新陈述为准。
- [x] MEM-03：`/memory` 能查看并删除条目；后台旧任务不得覆盖更新后的事实，也不得复活已删除记忆。
- [x] MEM-04：长期记忆提取失败不影响本轮回复与历史；后台运行时可立即提交下一轮消息，摘要/记忆本身不触发递归记忆提取。
- [x] MEM-05：后台任务以源轮次去重，结果提交前校验来源与版本；退出时保存待处理状态或明确取消，不在程序退出后继续不可见的模型调用。
- [ ] USAGE-01：界面分别显示当前上下文占用与累计消耗，累计请求 token 不能用作当前窗口占用。
- [x] USAGE-02：主对话、压缩和长期记忆使用同一配置模型，辅助请求用量单独记录且计入会话总量；每个请求 ID 只结算一次，后台结果归属原会话。
- [x] USAGE-03：API 未返回 usage 时显示未知或标记估算；有未知请求时总量标记不完整，不填零或假装精确。上下文估算与服务端结算分开。
