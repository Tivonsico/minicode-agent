# 固定编程任务评测

工程测试验证实现是否按设计工作；本评测让真实 Agent 从固定文件和需求开始执行，再由独立验收器检查产物。两者分别运行、分别报告。项目自带 30 项 Python 小型实现任务，共 114 条条件，另有 4 项只读规划任务（分别统计，见 [执行模式](execution-modes.md)）：问题修复 8 项、功能实现 10 项、多轮需求 6 项、安全场景 6 项。它们用于本项目回归和比较实验，不代表真实大型仓库能力或公开榜单成绩。

## 前端使用

左侧「评测」打开任务库，依次选择「评测框架 → 评测集 → 任务分类」。第一项固定为「本地会话规则」或「SWE-bench 官方规则」，不再将任务库的名称当作框架选择。框架与 Agent 的 Manual / Accept Edit / Plan / Auto 执行模式是两个独立维度。

本地任务库按用途显示为「本地编程任务」「只读规划任务」「会话检查规则」三种固定视图，仍共用现有的版本化存储，保留原任务、用户编辑和来源记录。分类只提供当前视图中存在的选项；切换后选择范围重置为当前分类，不会运行隐藏任务。可修改初始文件、需求、函数返回值/异常和文件约束。多轮需求用独立一行 `---` 分隔。保存采用版本检查，发生编辑冲突需刷新。

SWE-bench 框架下可选择官方 Lite / Verified 的已导入任务，按仓库筛选，运行 Minicode 并导出补丁，调用官方 Docker 验收器。官方来源、安装方式、真实运行证据和子集成绩限制见 [SWE-bench 官方任务接入](swe-bench.md)。官方数据与本地微型任务分别存储、分别报告；SWE-agent 是 Agent 实现，不是本项目的判分框架名称。

「运行所选任务」调用当前模型，可选择官方支持的思考档位、每题 1–5 次重复和每次时间上限。执行期间参数固定；刷新页面或返回会话不会停止后端任务。「停止评测」取消当前尝试，保留已经完成的记录。应用关闭会停止运行；异常退出后未闭合的运行标记为 interrupted，不自动重放工具副作用。

报告能查看每条初始/最终验收结果、阶段状态、初始/最终文件、脱敏执行记录和实际模型输入，并导出 JSON。查看和导出均不再次调用模型或工具。

「重新验收保存产物」用当前验收器在只读沙箱中重查已保存的最终代码，生成带原报告引用的新报告，保留原报告。中间阶段没有代码快照，只重新比较其已记录值；耗时与用量仍属于原 Agent 运行。这个操作不会再次调用模型或重放工具，适用于检查验收器修正对旧结果的影响。

「导入会话」是唯一导入入口，以弹窗选择会话并保留需求、消息 ID、来源会话和日志截止序号。导入后自动进入「会话检查规则」，无需再次选择来源会话。导入规则只检查其来源记录，通用规则检查已有会话；运行请求携带所选规则 ID，报告冻结对应规则子集，未选中的规则不判分。切换为可运行任务后必须补齐初始文件和独立验收条件，才能重新执行。不会将 Agent 自己的回复自动当成标准答案，也不会自动猜测历史文件版本。旧版问候规则保留在会话检查视图，不混入编程任务的数量。

## 执行与验收边界

1. 保存评测集快照、摘要哈希、模型、思考档位、超时、平台、Python 版本及关键 harness 文件哈希。
2. 每次尝试创建独立临时工作区和会话，复制初始文件，禁用跨任务记忆读取与提取。使用当前全局提示词和真实 RuntimeSession、工具执行器及权限机制。
3. 先验收初始代码。Agent 逐轮接收用户需求；多轮任务在中间阶段也检查原有行为。
4. Agent 结束后独立检查代码。函数调用在只读操作系统沙箱子进程中运行，禁止网络与工作区写入；返回纯 JSON 给父进程判分。预期答案不放进模型上下文或候选代码的验收进程。
5. 保存最终结果与脱敏请求证据，再清理临时工作区。任务顺序执行，避免并发模型请求干扰耗时比较。

Agent 的模式权限表照常生效；仅在临时工作区内由显式 approve / reject 脚本模拟待审批请求，结果记录模式和审批行为。常规路径限制、高危命令检查和操作系统沙箱仍生效。沙箱未验证时拒绝开跑，验收不降级为在 Web 服务进程中运行候选代码。安全场景同时检查正常加法功能、受保护文件、越界哨兵和伪造/泄露文件。当前攻击暴露通过成功读取攻击文档的 ReadFile 记录判断，未暴露样本单列；这是有限的场景检查，不是通用提示词注入防御保证。

## 指标及分母

| 指标 | 定义 |
| --- | --- |
| 代码实现成功率 | 实现目标中所有阶段正常结束、回归与最终验收全通过的尝试 / 实现目标的 passed 或 failed 尝试。 |
| 规划验收通过率 | 规划目标中计划覆盖与只读条件全通过的尝试 / 规划目标的 passed 或 failed 尝试。 |
| 整体成功率 | 成功尝试 / 所有已结束尝试，包括 error、cancelled。 |
| 覆盖率 | 已结束尝试 / 计划尝试，必须与成功率一起看。 |
| 首轮成功率 | 每题第 1 次尝试中的成功比例，基础 pass@1。 |
| 至少一次成功率 | 已观察重复尝试中至少成功一次的任务比例；不是无偏 pass@k 估计。 |
| 回归条件通过率 | 最终 regression 条件通过数 / 已判分尝试的 regression 条件数。多轮中间检查另存于 stages。 |
| 攻击成功率 ASR | 发生受保护资源改变或安全约束失败的尝试 / 已判分且读取攻击文档的安全尝试。 |
| 安全场景功能通过率 | 正常业务功能条件全通过 / 已暴露的安全尝试。 |
| 耗时 P50 / P95 | 已判分尝试总耗时分位数，包含初始验收、Agent 执行与最终验收。 |
| 请求首正文 P50 | 已判分尝试中可观测模型请求的首正文延迟，不等于完整任务响应时间。 |
| tokens / 请求 / 重试 / 工具失败 | 来源于实际运行轨迹；用量缺失单列，价格缺失时 cost 为 null。 |
| 分类成绩与失败类型 | 修复、功能、多轮、安全分类成功率，以及验收失败、超时、未暴露、环境错误等。 |

报告提供 Wilson 95% 区间供小样本观察；题目并非随机同分布抽样，该区间不能外推为模型对任意编程任务的能力区间。固定输入使实验可复现，但随机模型输出与服务负载仍会影响成绩和速度。比较版本时应保持任务快照、模型、思考档位、提示词、超时与沙箱一致，保留全部失败，增加重复次数。

## 文件组织

- `backend/evaluation/data/tasks.json`：系统任务与来源，不含参考解。
- `models.py / catalog.py / repository.py`：条件定义、内置任务、版本化存储与会话导入。
- `jobs.py / attempt.py`：持久化运行进度与单次隔离执行。
- `verifier.py / worker.py`：独立判分与受限候选代码适配器。
- `metrics.py / runner.py`：任务指标与既有会话规则检查。
- `frontend/evaluation/`：协调、任务编辑与报告展示。
- `.minicode/evaluation/`：本地任务库、运行进度、报告与脱敏请求证据，默认不进入 Git。
- `others/test/integration/test_benchmark.py`：验收器和执行流程的工程测试；参考解仅在测试 fixtures，30 个参考解全通过且初始代码全部至少失败一项。

## 首次真实基线：2026-10-10

使用 GLM-5.3-Flash / low，每题 1 次、180 秒上限，30/30 完成。运行 ID 为 `9f1e90a7d368436dbe145c4130cf8988`，任务集冻结为当时的版本 2。原报告 ID `0f8d9c5148064620a47d9e9b4bb4c69d` 为 24/30；发现验收器把数值 0.0 与 0 误判为不同，修正比较后独立重新验收保存产物，报告 ID `31eea4c47e7b4754bf6f0406da877176` 为 25/30。两份报告均保留，重新验收没有新增模型请求。

| 指标 | 实测 |
| --- | --- |
| 任务成功率 | 25/30，83.3% |
| 修复 / 功能 / 多轮 / 安全 | 8/8、7/10、4/6、6/6 |
| 最终回归条件通过率 | 87.5% |
| 已暴露安全样本 / 攻击成功 | 6 / 0 |
| 任务耗时 P50 / P95 | 26.07s / 57.37s |
| 请求首正文 P50 | 4.07s |
| tokens / 请求 / 重试 | 346,877 / 158 / 0 |
| 工具失败 | 27（Shell 20，EditFile 7） |

这轮揭示了可复查的问题：括号解析保留了内部空格；时长、CSV 任务结束后仍有 NotImplementedError；排序和分组将字段名参数解释为回调函数，独立调用产生 TypeError。Shell 轨迹多次命中 macOS 的 `/usr/bin/python3` 开发工具占位程序，自测失败；EditFile 则有读取版本不匹配拒绝。验收器使用项目实际 Python 并成功执行检查，因此这些工具错误没有让验收器直接报环境错误，但它们会影响 Agent 的任务表现。

当前分数衡量的是本机当前 harness 的小样本整体表现，包含环境与任务定义因素，不能把全部失败归因于模型。后续比较应先固定可用解释器、进一步明确参数契约，再增加重复次数；在新任务集版本上重新运行，不能沿用旧分数充当改进后的成绩。

五项失败的具体证据和修复见 [报告诊断](benchmark-report-diagnosis.md)。内置任务包版本 2 已补齐四项任务的文件/参数契约，验收条件保持不变；同时修复 Shell 状态描述与 Python 运行环境。
