# 自动模型能力解析验证

日期：2026-10-08。

## 已实现

- 配置层不再读取 `CONTEXT_WINDOW`；默认 OpenAI API 根地址，实际选择的模型名原样用于请求。
- 服务端 `/models/{id}`、`/models` 的有效窗口字段优先；标准响应缺少这些字段时，按端点和完整模型名查询 Models.dev。
- 未知网关需要明确 `MODEL_CATALOG_PROVIDER`；不根据模型名前缀猜窗口，不跨服务商套用同名模型参数。
- 24 小时缓存，按端点、模型、目录映射及凭据摘要隔离；过期/损坏重新查询，密钥不落缓存、不发送给目录、不随重定向转发。
- 应用输出预留与模型输出上限分开；输入预算同时服从窗口减输出预留和独立输入上限。
- 启动解析失败不创建 Runtime；`--check-config` 离线，`--check-model` 只查能力，`--refresh-model` 跳过缓存。

## 验证证据

- 完整回归：133 项测试通过；包括会话、上下文、工具、权限、前端接口、跨平台入口和模型能力解析。
- 模型能力新增测试覆盖：服务端字段优先、列表发现、完整模型匹配、未知网关、认证失败、重定向、错误字段、缓存失效/隔离、离线缓存、输出预算和输入上限。
- 原生 OpenAI 请求使用 `max_completion_tokens`；兼容服务商请求保留 `max_tokens`，离线 HTTP 测试验证原样模型名与请求参数。
- 对公开 Models.dev API 进行了无密钥查询，并用实际返回的数据验证 OpenAI `gpt-4.1` 与智谱 `GLM-5.3-Flash` 的端点匹配和能力解析。没有向模型生成接口发送真实请求，不把目录查询视为模型生成权限验证。

## 边界和来源

[OpenAI 模型查询接口](https://developers.openai.com/api/reference/resources/models/methods/retrieve)不含上下文窗口字段。[Models.dev](https://models.dev)为社区维护目录，不是服务商官方实时元数据接口；自定义部署限制可能不同。任意未收录模型且服务端不提供窗口时，无法可靠自动得知该参数，程序明确报错。
