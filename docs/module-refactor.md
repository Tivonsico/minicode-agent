# 模块整理与现有功能修复

本轮范围：按职责拆分现有后端、提高可读性、修复已复现的问题。不新增预算、工具、HTTP 字段或页面入口。

## 比较基线

使用开始本轮工作时的工作树作为基线，而不是直接使用 Git HEAD。开始时已有未提交的文件快照、验证和页面改动，本轮保留这些内容。基线副本与审查差异保存在被忽略的 `others/test_record/refactor-audit/` 下，不包含 `.env` 或真实运行会话。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `backend/runtime/loop.py` | 串联上下文准备、模型请求、工具执行和轮次结束 |
| `backend/runtime/model_step.py` | 单次候选回复的流式记录、部分回复保存、断流后的有界恢复 |
| `backend/runtime/verification.py` | 验证证据判定，以及每轮结束前的复核状态与次数控制 |
| `backend/conversation/store.py` | 本地 JSONL 会话日志、日志恢复、检查点保存 |
| `backend/conversation/metadata.py` | 从事件计算会话标题、摘要、状态和 token 用量 |
| `backend/storage/files.py` | 内部目录校验、原子 JSON 替换、文件和目录同步 |
| `backend/storage/redaction.py` | 两种事件存储共用的递归密钥脱敏 |
| `backend/storage/mysql_store.py` | MySQL 会话事务、占用与恢复，直接复用公共投影和脱敏函数 |

其他领域模块改为从 `storage.files` 导入文件持久化操作，不再为了写 JSON 文件而依赖具体的 JSONL 会话实现。旧的 `conversation.store` 导入入口和 `SessionStore.project_meta` 保留兼容，现有调用方可逐步迁移。

`ModelStep` 保存一个模型候选回复；`StreamRecovery` 按轮次持有恢复次数，避免在每次模型请求后重新获得恢复额度。`CompletionReview` 同样按轮次创建，保留现有验证重试上限和一次契约复核规则。

## 已修复问题

### 长期记忆保存失败后无法重试

原实现先改内存中的条目、来源和完成标记，再写文件。文件写入失败后，页面可能读到未保存的条目；同轮重试会被完成标记跳过。手工添加、编辑和删除也有相同顺序问题。

现在基于最近确认的状态构建候选副本，原子保存成功后才发布到内存。失败时保留最近确认的条目、版本和完成标记，允许显式重试。若文件替换成功而目录同步失败，磁盘结果仍可能不确定；重新启动时读取实际保留下来的原子文件，不承诺跨磁盘故障回滚。

回归测试覆盖提取结果保存失败后重试，以及手工增删改失败时保留状态和版本。

### 工具调用 ID 复用导致结果漏记

执行器没有自行写入结果事件时，主循环会补写。原实现只按 `call_id` 检查旧结果，不同请求复用相同 ID 会让后一次结果被跳过，随后对话投影误报为未知结果。

现在按 `turn_id + request_id + call_id` 检查，并为补写结果明确保存请求身份。回归测试通过同一轮两次复用 ID、返回不同结果的实际 AgentLoop 路径验证，断言两个结果均进入后续模型历史。

## 页面兼容问题

开发过程中，新页面曾向仍在运行的旧后端提交 `run_limits`，旧请求模型因此返回 `Extra inputs are not permitted`。预算功能已从本轮代码移除；页面、请求模型及运行接口恢复到原有结构。未关闭额外字段校验来掩盖不兼容。
