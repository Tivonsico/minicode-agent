## 实际实现

MySQL 已通过 RuntimeService 接入，不再只是说明按钮。所选模式只写一个主事件源：本地 JSONL 或 MySQL。Context 消息和有效摘要、程序状态、checkpoint、接单原文、操作意图与结果均可持久恢复；独立 ShortMemory 没有恢复。

MySQL 事件与会话/操作投影通过 InnoDB 短事务一起提交。工具先 PREPARED，再条件转 STARTED；提交确认后才执行。COMMIT 回执丢失会查询稳定 receipt ID，无法确认则冻结 writer。LLM、审批和文件/Shell 都在事务外。

checkpoint 与事件在一致边界保存，校验后按 covered_seq 查询后缀，审计历史继续保留。恢复不会自动执行工具。UNKNOWN 要求核实实际效果、旧执行者及全部子进程停止，结论与证据可靠保存后才解除阻塞。

同会话用持久 owner、序号行锁及版本检查保持顺序。工作区占用不自动过期，重叠目录不能同时写入；独立目录可并行。本地与 MySQL 共用协作式执行协调，持久执行域标记还阻止其他数据库或模式在异常退出后绕过。当前限定同一执行主机、同一应用根目录和单一数据库执行域。

数据库动作在有界线程池内执行，入口有背压，并保留任务身份。取消先等待已开始的提交动作完成，再清理占用；同 store 的完整动作共用锁，覆盖数据库提交和内存投影发布。HTTP 同会话命令也串行。

前端可读取真实存储状态、填写配置、检查连接并保存重启配置。未配置或不可用时明确报错，既不假启用，也不回退本地。密码不回显。异常 owner 或冻结 writer 可从侧栏核实；UNKNOWN 从检查点页逐项核实。
