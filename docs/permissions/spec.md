# minicode 严格权限系统规格

状态：需求已澄清，部分实现（2026-09-17）。会话目录授权、文件逐次审批、危险命令前置拒绝和 Shell 失败即关闭已接入；Windows Shell 隔离与受保护数据库边界尚未通过验收。本规格描述完整目标，不代表所有能力已可用。

目录默认行为已由 [工作目录规格](../workspace-skills-terminal/spec.md) 更新：应用目录不再自动授权；用户添加的工作目录成为相对路径的默认位置。下文提及“项目根自动授权”的旧场景仅作历史需求记录。

## 背景与目标用户

minicode 是在 Windows 终端中工作的 Python 编程 Agent。项目文件、工具输出和 Shell 命令都可能含有不可信内容；模型可能误解用户意图，也可能受间接提示注入影响。使用者需要明确知道 Agent 能访问什么、能执行什么，以及一次批准会带来什么效果。

本功能面向在本机项目中使用 minicode 的开发者。目标是让程序在工具执行前实施统一权限决策，并在重启或继续会话后保持同一边界。安全层不负责判断代码修改是否正确，也不把模型的自我约束当作权限控制。

## 能力清单

- 以当前项目为基础访问范围，允许用户给当前会话增加、查看和撤销多个本地目录授权。
- 额外目录授权随同一会话恢复，不传播到其他会话或项目；模型和项目文件不能自行授予权限。
- 在每次工具执行前，按资源范围和操作类型作出允许、拒绝或询问的统一决策；没有新的用户授权时，拒绝不能被另一工具绕过。
- Shell 命令命中危险命令黑名单时，在审批前直接拒绝；用户批准或会话目录授权均不能覆盖拒绝。
- 对用户声明为受保护的数据库，Shell 不得获得可删除该库的凭据或管理连接；登记状态由应用持久保存，不随会话切换消失；无法验证该资源边界时，Shell 不启用。
- 在授权目录中支持文件读取、搜索、新建、修改和单文件删除；文件工具继续保护敏感文件与内部数据。
- 文件新建、修改和删除逐次征得用户同意，批准只对应所展示的调用和当时的目标状态。
- Shell 每次调用都征得用户同意，通过资源边界检查后可以联网和写入授权目录内的普通文件；对 `.env`、私钥及 `.minicode/` 内部记录的读取取决于受保护数据库的凭据隔离，审批明确提示实际可读范围及外发风险。
- Shell 及其子进程只有通过经验证的系统级隔离才能运行；隔离不可用或验证失败时拒绝执行。
- Shell 可以读取但不能修改 `.minicode/`；无法证明内部记录对 Shell 只读时，Shell 不启用。
- 应用不主动把密钥传入 Shell 进程环境；受保护数据库的高权限凭据不得通过文件、进程环境或内部记录暴露给 Shell。文件工具的敏感文件保护不等同于已批准 Shell 的保密保证。
- 权限变更、批准、拒绝和执行结果保存在会话记录中；恢复会话时从记录重建授权状态。
- 每轮向模型提供当前实际授权范围，使上下文压缩和会话恢复后仍能正确使用路径。
- 终端界面提供可浏览的目录授权列表；审批先展示关键摘要，并允许用户在决定前展开和滚动查看完整差异或命令。

## 默认权限策略

| 操作 | 决策 |
| --- | --- |
| 在授权范围内读取和搜索普通文件 | 自动允许 |
| 新建、覆盖或精确编辑文件 | 每次询问 |
| 删除单个普通文件 | 每次询问 |
| 执行 Shell 命令 | 先检查危险命令黑名单及隔离条件；通过后每次询问 |
| 文件工具访问范围外、受保护或不合法目标；Shell 访问范围外或修改内部记录 | 直接拒绝 |

首批黑名单覆盖明显的磁盘清空或格式化、递归删除磁盘根、系统目录、项目根或授权目录本身、下载后立即执行远程脚本、强制推送，以及整库删除命令。命中时直接拒绝并记录原因。与用户提供的原文一致，黑名单不承诺覆盖所有危险写法；未命中仍须经过路径边界、逐次审批与 Shell 系统隔离，不能被描述为“安全”。获批 Shell 仍可写入授权目录内的普通文件。

例如，命令中直接出现 `DROP DATABASE` 可以被黑名单拒绝；若同一效果由脚本、数据库客户端、存储过程或远程 API 间接发起，通用 Shell 命令文本检查可能看不出来。对用户明确登记的受保护数据库，额外通过数据库自身的最小权限和 Shell 的凭据、管理连接隔离阻止删除；这些约束的有效性必须经过对应数据库和运行环境验证。未登记的外部数据库不在此结果保证内。

目录授权只扩大可访问的资源范围，不代替新建、修改、删除或 Shell 的逐次审批。越界等策略拒绝作为可识别的工具错误交给模型继续处理，硬边界对后续工具调用仍然有效；用户拒绝一次审批后，当轮 Agent 停止并等待新指令，不再寻找替代工具或重新申请。

## 非功能要求

- 权限以程序状态和操作系统约束为准；系统提示词仅告知模型现状，不产生授权。
- 危险命令黑名单检查先于任何审批；命中即拒绝，不提供覆盖入口。
- 路径检查必须处理规范化、符号链接、Windows 目录联接、重解析点、硬链接别名和目标在审批期间变化的情况；无法证明目标仍在范围内时拒绝。
- 用户不能授权磁盘根目录或 Windows 系统目录等过宽范围；目录授权只接受存在的本地绝对路径。
- 文件工具不得把受保护文件内容发给模型。Shell 使用受控环境变量，不主动继承应用密钥；受保护数据库的高权限凭据必须从 Shell 可见文件、内部记录和进程环境中排除。对其余可见的 `.env`、私钥及内部记录，获批命令可能读取、输出或通过网络发送，界面不能把这种调用描述成保密操作。
- 已批准 Shell 的输出在传给模型或写入会话记录前遮盖已识别的应用密钥和私钥内容；未被识别的秘密仍可能进入输出或经网络发出，审批提示不得暗示完全防泄露。
- Shell 的系统隔离必须覆盖其启动的子进程，并限制宿主文件访问；系统运行所需文件与隔离空间内的临时文件可供进程使用。
- Shell 对 `.minicode/` 的写入必须由系统隔离拒绝，避免通过篡改事件日志伪造授权或破坏会话恢复。
- 受保护数据库清单及连接边界由用户在可信界面维护，不从项目文件或模型文本加载；无法验证凭据隔离或阻断管理连接时，Shell 在启动前拒绝，不能让普通审批覆盖。
- 不能靠扫描文件内容证明高权限凭据不存在。若本地文件型数据库位于 Shell 可写目录中，必须让该数据库文件对 Shell 只读；做不到就拒绝 Shell。
- 授权和撤销先可靠记录，再影响下一次工具调用；存储失败、隔离初始化失败和权限状态不一致时不得放宽权限。
- 审批内容应足够让用户识别具体目标和影响；审批后须重新验证路径、目标版本与权限状态。
- 摘要不能隐藏会改变授权判断的信息；完整详情可在终端内查看，详情过长时应能滚动而非静默截断。
- 普通项目文件、工具输出和历史摘要均视为资料，不能修改权限策略。
- 经用户批准的联网 Shell 可能发送授权目录内的普通数据、敏感文件及内部记录；经遮盖处理的命令输出也可能进入模型上下文和会话日志。审批界面必须明确提示这些能力。禁止清单不会使任意命令的业务结果都变得安全。

## 设计骨架

权限状态由项目基础范围、当前会话的额外目录和固定保护规则组成。用户的斜杠命令更新会话授权事件；会话恢复时重放事件并重新验证目录，得到当前有效状态。Shell 调用先过危险命令黑名单，再检查资源边界，随后决定是否询问；命中黑名单或越界的拒绝不能被批准覆盖。真正的宿主文件边界由系统隔离实施。

文件工具统一使用同一组有效目录，并在实际读写前复核目标。Shell 通过单独的系统隔离执行通道运行，授权目录是它可接触的宿主工作数据范围；逐次批准后可写普通文件，内部记录始终只读。用户在可信界面登记受保护数据库；Shell 启动门槛还检查该库的凭据与管理连接隔离，必要时收紧原本可读的敏感文件和内部记录。审批界面、执行器和模型上下文都从同一份当前权限状态派生信息，避免三处各自维护不同名单。

交互继续使用现有终端界面。用户通过斜杠命令管理授权，也能在可浏览列表中查看并选择目录；审批界面以摘要为入口，用户可展开完整详情后批准或拒绝。

目录列表区分固定项目根与当前会话新增的目录，显示授权是否仍有效，并允许从所选额外目录发起撤销。受保护数据库及其边界验证状态也在可信界面可见。审批摘要始终显示操作类型、目标、影响范围及高风险能力；Shell 还突出联网及实际可读的敏感文件和内部记录。完整详情可在同一界面滚动查看，批准与拒绝始终可见；用户拒绝后显示停止原因并回到输入状态。

## 不在本期范围

- 把命令字符串黑名单当成足以覆盖所有危险变体的保证；通用 `ToolName(pattern)` 规则引擎、用户／项目／本地三级规则文件及“始终允许”自动学习。
- 多档权限模式、提示词实现的计划模式、跳过权限的运行模式。
- 跨会话共享目录授权、模型主动申请扩大目录、自动授权系统临时目录或网络共享目录。
- Windows 10 或其他操作系统上的 Shell 系统隔离；首版只验证当前 Windows 11 环境，不满足条件时 Shell 保持不可用。
- 目录递归删除工具、自动撤销 Shell 已造成的副作用、保证获批准的任意脚本不会破坏授权范围内的数据。
- 将项目仓库中的配置文件作为提权来源。
- 为此功能新建图形前端。

## 完成标准

按[验收清单](checklist.md)验证：黑名单命中直接拒绝，文件工具和 Shell 对授权范围内外的行为符合各自权限；新建、修改、删除与 Shell 每次触发明确审批；用户拒绝后停止，撤销、重启恢复、上下文压缩和隔离故障均保持正确边界。只有 Shell 的系统级目录隔离、内部记录只读以及已登记受保护数据库的凭据和连接边界通过实际故障用例后，才启用 Shell 执行。
