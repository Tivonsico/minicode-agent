# minicode 核心功能规格

状态：需求澄清完成；本地核心实现与自动化验证已完成，真实模型联调待完成（2026-09-10）。

## 背景与目标用户

minicode 面向在 Windows 终端中工作的开发者，使用 Python 构建。用户可以描述编程任务，由模型读取项目、修改文件、申请执行命令，并在中断后查看和继续会话。

本规格定义首版能力和边界。总体里程碑见 [核心功能总计划](../others/plan/minicode-core.plan.md)，具体配置、状态取值、限制及可观测结果见 [验收清单](checklist.md)，实施映射见 [任务列表](tasks.md)。

## 能力清单

- 通过环境配置接入用户指定的智谱官方模型，使用 OpenAI 兼容的消息与原生工具调用协议。
- 分别保存内部会话事件和发送给模型的消息，保留系统、用户、助手与工具的身份及工具调用关联。
- 执行用户输入、模型响应、工具执行、结果回传与最终回复组成的对话循环。
- 区分会话、轮次、消息和工具执行状态，最终回复仅表示当前轮正常结束，不代表用户任务已完成。
- 支持流式显示和持续保存已接收的内容，仅执行已完整接收且通过校验的工具请求。
- 提供读取、写入、精确编辑、单文件删除、Shell、文件查找与内容搜索工具。
- 对连续的独立只读工具调用并发执行，对文件修改、删除和 Shell 调用串行执行。
- 项目内读取和编辑自动执行，删除与 Shell 调用经用户逐次确认后执行。
- 文件工具限制访问当前项目，并保护敏感文件和内部运行数据。
- 修改已有文件前要求读取并检查文件变化，避免覆盖用户或外部程序的新修改。
- 为每个会话建立独立目录，持续保存原始事件、元数据以及超长工具输出。
- 允许用户选择已有会话、查看中断位置并主动继续，避免重放已经产生副作用的操作。
- 在原始历史之外维护模型上下文，按输入预算压缩旧消息和工具结果。
- 每轮正常最终回复后，在后台提取用户明确表达的长期信息，按项目隔离并保留来源。
- 在终端中提供输入编辑、流式回复、工具状态、审批、会话选择和用量显示，不添加像素画标志。
- 限制同一项目同时运行的实例数量，防止内部数据与文件写入互相冲突。

## 设计骨架

### 配置与模型接入

配置管理加载密钥、服务地址、模型及预算，提供不含真实密钥的示例。模型适配层处理协议差异、流式事件、工具调用关联、结束原因与用量；不要求模型把普通正文包装成自定义 JSON。系统提示词在每次请求的有效上下文中保留一份，不反复追加成历史用户消息。

### conversation：会话容器

管理会话标识、轮次、消息和事件，为持久化、界面和模型适配提供一致的数据来源。对外构造 API 消息时保持真实角色，不把工具结果冒充为助手回复。持久化历史与当前上下文是两种视图，不以压缩后的上下文替代原始记录。

### agent：提示词与执行循环

维护系统提示词、可用工具描述和主循环。模型选择工具和生成回复；程序校验参数、执行权限规则、调度工具、判定轮次状态及限制。提示词介绍项目、历史与记忆的访问约定，不嵌入过时的完整程序源码。历史与长期记忆由可信程序模块选择性加载，模型无权任意修改内部记录。

### tools：工具与执行器

注册器描述工具能力、输入结构、分类、风险及并发属性；执行器统一实施权限、路径检查、输入验证、取消、输出管理和调度。连续只读调用成组执行，修改或 Shell 是顺序分界，不与其他工具重叠。

文件路径解析必须考虑项目外引用、符号链接及 Windows 目录联接。Shell 工作目录位于项目，但首版不提供操作系统级隔离；审批是命令执行的授权流程，不能被描述为限制 Shell 访问项目外文件的沙箱。

### memory：事件存储与长期记忆

源码模块与项目内运行数据分开。每个会话的追加日志保留原始事件，元数据保存可重建的汇总。超长工具输出放在该会话目录内，主日志保留相对引用；程序向模型提供可分段读取的定位信息。

长期记忆只保存用户明确表达的偏好、约束和事实，保留来源，允许查看和删除。新旧明确陈述冲突时以最新陈述为准，不将模型猜测或工具输出自动当作用户事实。后台工作失败不影响正常回复或历史保存，也不阻塞后续用户输入。

### context：上下文预算与压缩

使用已配置并核实的模型窗口，为输出保留预算，统计有效输入的占用。优先分段读取大文件并压缩较早工具结果，保留当前任务、必要近期消息、摘要及文件定位信息。调用与结果关联始终保持完整。

压缩采用生成候选结果、检查后替换的方式。失败则保留原上下文；仍能容纳下一请求时继续，无法容纳时保存并暂停，不静默丢弃历史。累计消耗与当前上下文占用分别展示。

### app：终端交互

负责输入编辑、流式输出、工具审批、状态与用量显示。执行期间可编辑但不能提交或排队新消息；正常结束后可提交，提前提交需先中断当前轮。选择旧会话只加载历史，用户主动继续后才恢复执行。

## 非功能要求

- 可恢复性：中断或进程异常退出后可读取已经持久化的片段与事件，不将半截工具参数当作可执行操作。
- 数据一致性：主日志为事实来源，汇总可重建，超长输出引用不逃逸所属会话目录。
- 可解释性：区分正常最终回复、输出截断、错误、中断和因限制暂停，记录工具审批及执行结果。
- 权限可控：审批绑定具体操作，拒绝不会触发自动重复申请；文件操作不绕过路径和敏感文件规则。
- 取消可见：中断停止后续调度并尝试终止运行中的进程，已发生的文件修改不会自动撤销，结果不明的操作不会自动重跑。
- 预算可见：主对话与辅助模型请求分别统计，服务未返回的消耗不伪装成零。
- 测试可复现：主要流程通过可控模型响应和临时项目验证，真实服务验证单独记录前提和结果。

## 完成判定

用户能在终端启动项目会话，让模型查找、读取和编辑文件，确认执行命令或删除文件，看到最终回复与用量；能中断、重启、选择会话并继续，且不会重复执行已完成的副作用操作。压缩不改写历史，后台记忆不阻塞交互。权限、失败和恢复行为通过验收清单验证后，才可标记首版完成。

## Out of Scope

- Web 界面、像素画标志、图片或视频交互。
- 多 agent、插件市场、远程执行、向量数据库、跨项目长期记忆。
- 同项目多个并行运行实例，以及执行期间的新消息排队。
- 文件工具访问项目外文件、目录递归删除工具。
- Shell 的操作系统级沙箱与对所有命令副作用的自动回滚。
- 模型推断的用户画像、自动重放结果不明的命令。
- 未经用户要求替换模型，或把未验证的接口能力当作已支持。
