# 工作目录、技能与终端呈现

状态：已实现并通过自动化验证（2026-09-17）。

技能部分的后续修订以 [技能系统规格](../skill-system/spec.md) 为准。

## 背景与目标

minicode 的安装目录保存配置、会话与源码，不能自动成为 Agent 的任务工作区。用户希望明确添加项目目录后再让 Agent 查找或修改文件，同时使用技能指导任务，并能在终端中查看简洁的工具状态与按需展开的详情。

## 能力

- 新会话默认没有工作目录；文件工具请求引导用户添加目录。
- 用户可为同一会话添加多个工作目录、浏览、撤销并选择相对路径使用的默认目录；重开会话恢复这些选择。
- 应用目录及其父目录、子目录不允许作为工作目录；内部输出只允许通过当前会话的受控输出引用读取。
- 用户询问 Agent 功能时，Agent 根据程序提供的能力信息回答，无需读取安装目录源码。
- 技能系统的完整行为见 [技能系统规格](../skill-system/spec.md)；技能不能扩大工具权限。
- 工具调用在终端中默认显示简短状态，用户可点击或用键盘展开结果并浏览历史。
- 启动脚本提供独立 Windows 控制台，无法使用交互控制台时显示可理解的错误。

## 非功能要求与设计骨架

目录授权与技能选择记录在会话事件中，恢复时重新验证目标；文件工具每次都用当前授权和实际路径检查。工具详情继续保存在会话记录中，但主屏输出有界。技能文本来自明确选择的本地文件，被视为任务资料，不能覆盖系统权限。常规测试在一分钟内完成。

## 范围外

本功能不宣称 Shell 隔离已通过验收；Shell 继续不可用。技能资源的远程安装、自动发现外部技能仓库以及图形桌面前端由后续任务处理。
